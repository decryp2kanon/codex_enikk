## 어휘 구조와 경계

CODEX_ROOTS를 기존 TECH_ROOTS에 setdefault로 합친다. 기존 검증된 읽기와 중복되면 새 읽기로 덮어쓰지 않는다. load 시 PROSE_READINGS를 구성해 기존 단일 token scan/lookup을 그대로 사용한다. 새 regex chain, 외부 backend, 매 호출 파일 reload는 없다.

snake_case는 명시적으로 한정한 상태-label 문법이다. prefix apply/response/tool/rollback과 suffix patch/item/call/result/point를 load 시 조합한다. 5개 교육 label만 외우지 않고 tool_item/response_call/response_result/tool_point/rollback_result/apply_item 등 신규 label에도 적용된다. 임의 prefix/suffix나 세 구성요소는 분해하지 않는다. tool_call_id/get_tool_call/tool_custom/custom_response는 원문 그대로다. bare tool_call처럼 실제 변수명과 status label이 같으면 문맥 없는 입력의 의도를 구분할 수 없다. bare 등록 label은 낭독하고 inline/fenced code, URL/path/email/options/대입 expression 내부는 보존한다.

기존 영어 어근의 복수형 +스 정책을 재사용한다. 기능어를 복수형 어근으로 확대하지 않는다. 한국어 조사와 Title Case도 같은 registry를 재사용한다. plural 철자 표기는 기존 custom 정책이며 실제 음성의 영어 유성/무성 동화를 검증했다고 주장하지 않는다.

새 전체 문장/교육 행 전용 exact override는 0개다. lexical 단어 및 status-label token lookup은 존재하며 이를 lookup 자체가 없다는 의미로 주장하지 않는다. 런타임은 corpus/fixture를 읽지 않는다.
