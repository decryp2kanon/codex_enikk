## 구조와 읽기 정책

단일 glyph atom, 조합 operator registry, 반복 개수 문법을 사용한다. 길이가 긴 조합을 먼저 처리한다. 1~8회 반복 atom table은 source와 무관하게 startup에서 일반 문법으로 생성하고, 더 긴 반복은 같은 문법으로 처리한다. 기존 PROSE_READINGS lookup에 이 token registry를 합쳐 기존 어휘 hot path에 추가 scan을 넣지 않는다. 전체 문장/교육 행 전용 literal override 추가는 0개다. 기호 token 자체의 공통 registry lookup은 존재하며 이를 lookup이 없다는 뜻으로 주장하지 않는다.

독립된 `##`는 해시 이 개, 실제 heading `## 내용`은 이 단계 제목 내용이다. heading 1~6을 구분한다. 독립된 별표/밑줄/백틱 등은 문자명과 개수를 읽고, Markdown emphasis에서는 굵게/기울임/취소선/강조 끝 구조를 읽는다. 비교/논리/시프트/화살표는 조합 명칭을 사용한다. '<!--'와 '-->'는 주석 시작/끝, 완전한 주석은 주석 내용 및 종료를 읽는다. 간단한 HTML tag는 열림/닫힘과 tag 이름을 읽는다.

Markdown 장식은 기존 notify clean_text에서 사라지므로 장식 제거 전에 같은 custom module의 markdown_spoken을 호출한다. custom module은 load 시 한 번 import하며 외부 backend/model을 초기화하지 않는다. 최소 설치 환경에서 module이 없으면 기존 전처리로 안전하게 돌아간다. 원문은 수정하지 않고 별도의 spoken 문자열만 만든다.

완전하거나 닫히지 않은 backtick/tilde fence의 실제 코드 내용은 계속 숨긴다. standalone fence 기호는 normalizer/notify direct call에서는 문자명으로 읽지만, stream의 기존 fenced-code 차단을 우회하지 않는다. 따라서 원본 fence 행의 실제 production playback을 확인했다고 주장하지 않는다. inline code는 구조 낭독 parser에서 보호하고 기존 inline-clean 정책을 유지한다.

URL/path/email/version/IP/SHA/identifier/CLI option/명시적 code token 내부는 분해하지 않는다. space-separated ASCII 비교/대입 expression은 code literal로 보존한다. prose 기호와 실제 코드가 같은 철자를 갖는 모호한 경우를 완전히 자동 판별한다고 주장하지 않는다.

## 한계와 후속 반영

HTML attributes 전체 grammar, shell grammar와 Markdown의 모든 문맥을 구현하지 않는다. `<<<`, `--`, `//` 같은 독립 표기는 glyph/count 정책이며 shell redirect/options/comment 의미는 명시적인 코드 문맥으로 구별한다. 영어 tag 이름/실제 Chatterbox 발음은 청취 미검증이다. 바뀐 heading/emphasis spoken 정책은 장식을 생략하던 기존 정책보다 설명이 길어진다.

승인 후 main FF/push, TTS만 update/restart, active release 및 ready/model_ready/playback_available/source-install parity를 확인한다. Enikk core는 건드리지 않는다.
