## Changed flow

Path normalization remains once per engine request. Scalar number/unit/registered lexical fast paths remain. Mixed prose uses one maximal-token walk with original offsets, approved value/counter/suffix decomposition, adjacent unit consumption, and existing hash/UUID/quantity/cardinal/lexical renderers. Already-spoken Korean is not repeatedly sent through another value replacement pipeline. Unit lookup remains case-sensitive; machine tokens are not decomposed to find matching numbers.

Twelve Korean phrase/weekday protection scans and protected-marker restoration are omitted from independent production, because it never calls the third-party normalizer those shields were written for. Their checked loss/duplication contract remains in the optional callback compatibility branch. The 46/48/61 count protection is no longer used by independent production: shared numeric-counter grammar handles these and unseen counts. No new whole-input/hash/UUID/sentence exact mapping was added.

Nested valid JSON containers retain whitespace and literal values. Code, URL/path, filename, option and identifiers retain boundaries; a single inline hex immediately after an approved label still follows existing hash policy. Heading lines inside code fences are not interpreted before code protection. Shared suffix dispatch is used by numeric, hash, UUID and lexical candidates, with verb suffixes restricted to lexical words.

The engine file is byte-identical to the start state. Long-tail warning/playback, 170ms tail attenuation, voice/reference/model/sampling/tempo/retry/guard/chunking/sequence-gap are unchanged.
