기대값과 원본 600개 전체 표는 `tests/fixtures/education-2-7.json`에 고정되어 있다. 숫자 기대값은 production 함수를 사용하지 않은 별도 자릿수 분해 계산과 명시적인 작은 수/큰 수/소수 anchor로 검증했다. 어휘·경로 기대값은 이번 교육에서 선택한 낭독 정책이며, 사용자가 300개 발음을 직접 청취·확정했다고 주장하지 않는다.

- 2번: 완전한 scalar 숫자에 한해 부호와 정수/소수를 한국어로 읽는다. 양수 부호는 플러스, 음수 부호는 마이너스, 소수점은 쩜, 소수부는 자리별로 읽는다. 32자리 정수까지 지원하며 더 큰 값은 원문을 유지한다. 기존 cardinal 함수를 경·해·자·양까지 확장해 조보다 큰 자릿값이 누락되는 문제를 막았다. 기존 방식의 일만/일억 등 만 단위 묶음 표기를 유지한다.
- 3번: 유효한 세 자리 쉼표 grouping만 허용한다. 소수/부호/큰 수 처리를 2번과 공유한다. malformed grouping과 leading-zero 문자열은 자동으로 일반 숫자로 해석하지 않는다.
- 4번: Bitcoin 용어의 공유 lexical root와 합성어 구성요소, 약어 alphabet을 사용한다. mempool, pubkey, scriptpubkey 등은 구성요소로 조합한다. 공통 어근의 복수형도 별도의 전체 문자열 mapping 없이 처리한다.
- 5번: Git 어휘와 실제 등록된 hyphen compound만 분해한다. 일반적인 임의 branch-name/identifier를 hyphen만으로 분해하지 않는다. 새로운 prose 문장과 등록 어휘에 붙는 한국어 조사에서도 같은 규칙을 재사용한다.
- 6번: 의미 있는 command 어휘는 공유 root로, 약어는 공통 알파벳 읽기로 처리한다. 불확실한 관용 발음을 임의로 확정하지 않고 chmod, passwd, rsync 등 일부 명령은 보수적인 철자 읽기를 채택했다.
- 7번: Bitcoin/Sugarchain 프로젝트 경로에 한해 prefix/directory/basename/extension/version을 조합한 설명을 만든다. 루트/홈/현재/상위 경로와 숨김 디렉터리를 구별하고 중간 `..`를 해소하거나 없애지 않는다. 원문과 대체 span을 receipt용 기록에 그대로 유지한다. 기타 경로는 기존 basename 설명 정책을 유지한다. 실제 파일시스템 조회는 없다.

미학습 검증은 숫자 20개, grouped 숫자 20개, 각 어휘 영역의 새로운 prose 20개씩, prefix/새 filename/version/extension을 조합한 경로 20개다. 추가 복수형, 경계, 코드, 범위 및 원문 기록 검증도 포함한다.

## 경계와 구조

- URL/email/filename/path/version/IP/SHA/underscore identifier/CLI option/code-token 내부의 어휘·숫자 변환을 보호한다. 기존 Enikk/Yuki 이름 치환도 같은 literal 경계를 지키도록 보완했다. inline/fenced code는 기존 heard-error 처리보다 먼저 보호한다. URL query에 포함된 경로도 경로 낭독 대상으로 잡지 않는다.
- 명시적인 project path 설명은 7번의 의도된 별도 변환이며, source 문자열 자체를 변경하지 않는다. engine의 기존 `normalize_paths -> normalization` 연결점은 그대로다.
- 신규 전체 문장·숫자 값·경로 literal override는 0개다. 런타임은 corpus/기대값 파일을 읽지 않는다. 실제 어휘 사전의 lexical token lookup과 등록된 compound/abbreviation 집합은 존재하며, 이것을 “lookup 자체가 0개”라고 주장하지 않는다. 기존 custom narrow exception은 보존했다.
- 경로 구성요소 읽기만 최대 256개 bounded LRU cache를 사용한다. 전체 경로를 외우거나 저장하는 cache는 아니다. 규칙 및 path pattern은 load 시 구성한다.
- custom-only 모드에서는 Latin 문자/숫자가 없는 입력이 원래와 동일한 결과를 내므로 보호/복원 identity pass를 생략한다. 명시적인 callback을 사용하는 기존 보호/복원 API는 유지했고 parity test로 비교했다. 기존 주입 custom module의 callback 호출 계약도 별도 테스트로 보존했다.
- 표준 라이브러리 `re`와 `functools.lru_cache`만 사용한다. 외부 normalizer/backend를 추가하지 않았다. Chatterbox engine/runtime/streaming/guard/retry/model/reference/voice 파일 및 설정은 수정하지 않았다.

## 충돌과 미확정 항목

- bare HEAD/main/source/command 단어는 prose와 machine identifier가 같은 철자를 사용한다. 이번 corpus의 bare token은 용어로 읽지만 코드 표시·옵션·파일/경로·식별자 내부는 보호한다. 문맥 표시 없는 동일 문자열의 의도를 자동으로 판별한다고 주장하지 않는다.
- 4~6의 어휘 및 약어 읽기는 텍스트 정책 후보다. 관용 발음과 실제 Chatterbox 발음은 후속 청취에서 확정해야 한다.
- 7번은 기존 축약 basename 설명과 달리 project 경로의 전체 구조를 설명하여 출력 문장이 길어진다. 음성 길이·TTS RTF·첫 소리 결과는 미측정이다.
- 숫자 범위는 32자리로 명시했다. 범위를 넘거나 숫자와 identifier를 구별할 수 없는 문장 내부의 raw number에는 새 scalar 규칙을 적용하지 않는다.
